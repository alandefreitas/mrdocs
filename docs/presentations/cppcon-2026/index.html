What Mr.Docs is

A C++ reference documentation generator built on Clang/LLVM.

It reads your project's source through a compilation database, builds a complete symbol corpus from the real Clang AST, and emits documentation in several formats.

The same corpus feeds rendered documents for human readers and structured data for downstream tools.

Key words: compilation database, symbol corpus, real Clang AST. One corpus, many outputs.

Install

Binary packages

Grab a release from the GitHub Releases page. Most users start here.

Two paths: a prebuilt binary, or build from source with the bootstrap script. We'll auto-animate to the source path.

Install

Build from source


git clone https://github.com/cppalliance/mrdocs.git
cd mrdocs
python bootstrap.py

The script provisions every dependency (LLVM, Clang, third-party libs), configures, and builds. Add --yes for non-interactive installs.

Prerequisites: Python, a recent C++ toolchain, CMake, Git. Pass --install-system-deps if any are missing. Verify with `mrdocs --version`.

Driving Clang: the compilation database

Mr.Docs drives Clang with a compilation database: the per-file list of compile flags. That's what lets it see the code with the right include paths, defines, and language standard.

compile_commands.json

You already have one. Mr.Docs reads it from disk.

CMake

Point at CMakeLists.txt; Mr.Docs configures and reads the generated database.

Header scan

No build system. Mr.Docs walks input and synthesizes one.

The one design choice

Only valid C++

Mr.Docs parses the source as the compiler does, so symbols come from a real AST rather than from text.

r-fit-text scales that line to fill the slide. Almost every difference from other tools flows from this decision.

Idioms without workarounds

Other tools need a doc-only declaration guarded by a macro — two versions of the same symbol:


#ifdef DOXYGEN
// what the docs should show
using scope_token = /* implementation-defined */;
#else
// what actually compiles
using scope_token = detail::scope_token_impl<Tag>;
#endif
The source carries two versions. This is the workaround Mr.Docs removes.

Idioms without workarounds

Mr.Docs reads the real declaration; configuration expresses the intent:


using scope_token = detail::scope_token_impl<Tag>;
      

# mrdocs.yml
implementation-defined: ['logr::detail::scope_token_impl']

The synopsis renders /* implementation-defined */; the documented C++ stays the compiled C++.

Same effect from the doc comment with @implementationdefined. Also: see-below, include-symbols, overloads.

Configuration

One YAML file (or CLI flags) shapes the whole run. The options group into:

  • Inputs — where the code is, how to compile it
  • Filters — what enters the corpus
  • Extraction — how much detail to pull
  • Output — generator, destination, layout
  • Diagnostics — how strict to be about problems

Every option has a CLI equivalent; the full list lives in the Configuration Reference.

Placeholder grouping for the feature pass — reorganize the option taxonomy later as you prefer.

Generators

A generator turns the corpus into output. Three ship built in:

HTML

The default. Self-contained pages, bundled stylesheet, serve from any static host.

AsciiDoc

Source for AsciiDoc tooling and Antora. Fold the reference into a larger site.

XML

Structured intermediate. Diff the corpus across releases, or test its shape.

Data-driven starting points also ship: Markdown, LaTeX, JSON Lines.

A new format via a data-driven generator is cheap: a directory of Handlebars templates plus a manifest.
