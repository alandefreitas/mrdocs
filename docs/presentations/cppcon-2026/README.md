# Mr.Docs presentation, CppCon 2026

The slide deck for the CppCon 2026 talk "MrDocs: Reliable Reference Documentation for C++ Using the Clang AST" (Thursday Sep 17, 2026, 2:00 PM).

A [reveal.js](https://revealjs.com) slide deck introducing Mr.Docs. The content mirrors the project documentation. The theme is built from **CppCon's own palette**, not the Mr.Docs brand: on YouTube the slide is shown inside CppCon's navy frame, and that recording is what almost everyone sees. [DESIGN-NOTES.md](DESIGN-NOTES.md) has the sampled colours and the reasoning; [FIGMA-DESIGN-NOTES.md](FIGMA-DESIGN-NOTES.md) still documents the Mr.Docs brand, which owns the two cover slides.

## Status

This deck lives on the `docs/cppcon-2026-presentation` branch only. It is not merged into `develop` and nothing in the build or the Antora site picks it up: `docs/presentations/` is inert as far as CMake and the playbook are concerned. After the conference it can become part of the published documentation, get served from the website, or just stay here.

## Conference requirements

- **Slide 1 is CppCon's title card**, which they require and which drives the YouTube title. It is already in place; see "The CppCon title card" below for the one thing left to do with it. The pipeline enforces it (check S1) and its 16:9 shape (S18).
- **Export a PDF after the talk** and upload it to the session's Discord channel and the CppCon slides Dropbox request.

## Plan first

The content is not written in HTML. It is written top down in `plan/levels/` (criteria, meta, plan), each file validated against a JSON schema in `plan/schemas/` and checked against the level above it by `plan/tools/pipeline.py`; `plan/build/index.html` is generated from the slides file. Every claim in `research/HOW-TO-GIVE-GREAT-TALKS.md` is mapped in `plan/levels/0-criteria.yml` (level 0, generated, with its own schema) to the check that enforces it, and `python3 plan/tools/pipeline.py report` prints which claims the deck currently meets. [plan/PLAN.md](plan/PLAN.md) explains the levels, the checks, and the decisions the checks forced. The hand-made `index.html` at this level stays until the generated deck is reviewed and replaces it with `pipeline.py build --out index.html`.

## Slide order

Slide 1 is CppCon's title card (see below). After that the deck follows the documentation nav (Getting Started → Commands → Configuration → Generators → Extensions → Design Notes): title, what it is, the pipeline, **demo gallery**, install, basic usage, migration notes, documenting the code, configuration, generators, extensions, why-automate, closing. **All slides are horizontal** — there are no vertical (down-arrow) stacks. ## reveal.js features in use

- **Auto-animate ("magic move")** — `data-auto-animate` on consecutive slides morphs shared elements. Used for the config file growing line by line, the implementation-defined idiom collapsing from two declarations to one, and the **doc-comment buildup** (a stable `sqrt` signature with the comment growing around it).
- **Code line-number stepping** — `data-line-numbers="1|3|4|5|7-8"` walks through sections of the same code block with the arrow keys (the doc-comment slide).
- **Native mermaid** — the mermaid library, driven manually so it renders only **after** the web fonts load (rendering earlier sizes the node boxes for a fallback font and the Lexend text then clips). The pipeline graph and the redundancy-vs-convenience quadrant chart reuse the same definitions as the docs. Diagrams are `<pre class="mermaid">…</pre>` (no `<code>` wrapper — the highlight plugin would otherwise mangle them).
- **Live website backgrounds** — `data-background-iframe` with `data-background-interactive` puts mrdocs.com (and the live Mr.Docs library reference) behind the slide; click to scroll it without leaving the deck.
- **Reference docs in production** — the demo section shows real published reference docs: Boost.URL's `url_view` page on boost.org (a captured screenshot, since boost.org blocks live framing) followed by Mr.Docs documenting *itself* live on mrdocs.com (dogfooding).
- **Speaker notes** — `S`. Every slide has them, including the keyboard-shortcut cheat sheet (on the title slide's notes).
- **Other** — per-slide transitions (`data-transition="zoom"`), `r-fit-text` for the big "Only valid C++" line, fragments (including highlighted table rows), background gradients, slide overview (`ESC`), search (`Ctrl`+`Shift`+`F`), and zoom (`Alt`+click).

## Editing

- Slides are plain HTML `<section>` elements in `index.html`. Keep them all top-level (no nesting) to stay horizontal-only.
- Speaker notes go in `<aside class="notes">`.
- Theme lives in `css/mrdocs-theme.css`. Colours come from CppCon (see `DESIGN-NOTES.md`): `--cc-navy` (`#273457`) is the canvas, `--cc-gold` (`#FFBB33`) is the accent, `--cc-orange` (`#FF8933`) is the 2026 spot colour; type is Lexend, with Bangers reserved for the covers.
- Layout helpers: `.columns`, `.cards`/`.card`, `.lead`, `.muted`, `.tag`, `.centered`, `.scrim` (darkens an iframe background for legibility), `.url-chip`, `.demo-card`.
- Mark a slide as a cover (hides the corner mascot, the arrows, the progress bar and the slide number; used for the title card, title and closing) with `data-state="cover"`.
- **Do not give a slide its own background.** The canvas is CppCon's own gradient and the deck depends on it being continuous from the title card onward; see `DESIGN-NOTES.md`.

### The live Boost.URL slide (framing a third-party site)

boost.org sends `X-Frame-Options: SAMEORIGIN`, so its pages can't be embedded in an
iframe from another origin — the browser enforces this and the embedding side can't
override it. The workaround used here: **bundle the page locally**. `single-file-cli`
inlines all CSS/fonts/images into one self-contained HTML
(`assets/boost-url-live/url_view.html`); served from this deck's own origin, it frames
freely and stays interactive (scroll/links work; nav scripts are stripped). Fully offline.

Regenerate it after a docs change:

```bash
npx -y single-file-cli \
  --browser-executable-path="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --browser-wait-until=networkidle0 \
  "https://www.boost.org/doc/libs/latest/doc/antora/url/reference/boost/urls/url_view.html" \
  "assets/boost-url-live/url_view.html"
```

`assets/boost-url-production.png` is a 2x static screenshot of the same page, kept as a
fallback (swap the slide's `data-background-iframe` for `data-background-image` to use it).

Other ways to frame a header-protected site live (not used here, but viable on your own
machine): an "Ignore X-Frame headers" browser extension, or a small local proxy that
strips the header before re-serving.
